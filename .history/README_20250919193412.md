## DevOps Infrastructure (Mock, No Real AWS Connection)

This repository contains Terraform configuration that models a complete DevOps infrastructure on AWS with components: VPC, EKS, RDS/Aurora, ECR, Jenkins, Argo CD, Prometheus, Grafana. The configuration is built to allow `terraform validate/plan` without real AWS access (local backend, fake keys, conditional resource names like `chernous_fp_devops-*`).

### How to Run Local Validation

1. Install Terraform 1.5+.
2. In the repository root, execute:

```bash
terraform init
terraform validate
terraform plan -out=tfplan
```

State is stored locally in `state/terraform.tfstate`.

### Acceptance Criteria (Without Real AWS)

- After `terraform plan` you will see resource creation with naming:
  - VPC: `chernous_fp_devops-vpc` with public/private subnets and NAT
  - ECR: `chernous_fp_devops-ecr`
  - EKS: `chernous_fp_devops-eks`
  - RDS: `appdb` (Postgres 14.10)
  - Jenkins/ArgoCD as `helm_release` with namespaces `jenkins`, `argocd`

### Mock Cluster Validation

Since there's no real cluster, the commands below are provided as a reference for production environment validation:

```bash
kubectl get all -n jenkins
kubectl get all -n argocd
kubectl get all -n monitoring

kubectl port-forward svc/jenkins 8080:8080 -n jenkins
kubectl port-forward svc/argocd-server 8081:443 -n argocd
kubectl port-forward svc/grafana 3000:80 -n monitoring
```

### Environment Variables

Create a `.env` file from `env.example` and customize values:

```bash
cp env.example .env
# Edit .env with your values
```

Main variables can be set via environment variables or defaults in `main.tf`:

- `PROJECT_PREFIX` → `project_prefix` (default: "chernous_fp_devops")
- `AWS_REGION` → `aws_region` (default: "us-east-1")
- `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` — AWS credentials
- `DB_USERNAME`, `DB_PASSWORD` — Database credentials
- `JENKINS_ADMIN_PASSWORD`, `ARGOCD_ADMIN_PASSWORD`, `GRAFANA_ADMIN_PASSWORD` — Service passwords

### CI/CD (Jenkins + Argo CD)

- Jenkins and Argo CD are defined as `helm_release` in modules `modules/jenkins` and `modules/argo_cd`.
- For real environment, you need to set valid `kube_host/kube_ca/kube_token`.

### Monitoring (Prometheus, Grafana)

- Add your own module/chart in `modules/monitoring` with Helm releases `kube-prometheus-stack` or separately `prometheus` and `grafana`.

## Execution Steps (According to Requirements)

1. Environment Preparation

- Initialize Terraform: `terraform init`
- Check variables (see `main.tf`): `aws_region`, `project_prefix`, `db_username`, `db_password`

2. Infrastructure Deployment (Mock)

- Run plan: `terraform plan`
- In real environment it would be: `terraform apply`

3. Service Availability Check (For Real Cluster)

```bash
kubectl get all -n jenkins
kubectl get all -n argocd
kubectl get all -n monitoring
```

Port forwarding:

```bash
kubectl port-forward svc/jenkins 8080:8080 -n jenkins
kubectl port-forward svc/argocd-server 8081:443 -n argocd
kubectl port-forward svc/grafana 3000:80 -n monitoring
```

4. Monitoring

- Open Grafana (real environment): http://localhost:3000 after port-forward
- Check dashboards and metrics
